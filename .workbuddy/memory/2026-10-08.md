## Fable 5 直连实测（i-token.ai 中转）——独立套件 `fable5_direct/`

用户给定 `https://i-token.ai` + key，要求「不用本系统，直接测」fable5 的基础/增强/专项/契约健壮性。
→ 新建**独立直连**套件（不经平台 runner / Web / 队列）：`fable5_direct/{harness.py,cases.py,main.py,make_report.py}`，
77 条用例（基础 15 / 增强 20 / 专项 11 / 契约 20 / 满血指纹 11），逐请求落盘 `requests.jsonl`。
报告：`fable5_direct/REPORT-fable5-itoken-2026-10-08.md`（+ 同名 .html）。
复核后：**通过 54 / 失败 0 / 警告 14 / 未验证 9**（已评估通过率 100%）。

- **信任级发现（最重要）**：该中转的 `usage` 是**由 `max_tokens` 推导的伪造值**，不是真实计量。
  铁证：同一提示「只回复 OK」，`max_tokens=64→output_tokens=64/think=63`，`max_tokens=100→100/99`；
  批次内 **38/72** 条 200 响应 `output_tokens == max_tokens`；**23 条内容完全不同的请求**
  （S01–S09 九种 beta 等）`thinking_tokens` 全为 255；流式 `message_start` 报 1、`message_delta` 报 100。
  最强证据：`max_tokens=100` 要求输出 1..60，正文 170 字符自身已超 100 token，usage 仍报 100/99。
  → 派生结论：`output_tokens == max_tokens` 时 `stop_reason` 仍为 `end_turn`（38 条），**截断不可判定**。
- **`i-token.ai` 是 New API 系中转**：报错体泄露分组名 `ccmax`；**按 `max_tokens × $50/M` 预扣额度**，
  余额不足返 403 `token quota is not enough, token remain quota: $X, need quota: $Y`。
  本轮把余额从 $0.913 耗到 $0.006（现约 $0.012）→ 8 条用例无法取证，**该通道不能做长输出压测**。
- **文档承诺的 400 普遍未执行**：`thinking={disabled}` / `{enabled,budget_tokens}` / `temperature` /
  `top_p` / `top_k` / 末尾 assistant(prefill) / 缺 `max_tokens` / 非法 role / 非法 `effort` 值 /
  缺 `anthropic-version` → 线上**全部 200 静默接受或静默丢弃**。已执行的校验只有：空 `messages`→400、
  畸形 JSON→400、无效 Key→401、未知模型→503 `无可用渠道`。
- 端点缺失：`POST /v1/messages/count_tokens` → 404 `Invalid URL`（该站未实现）。
- OpenAI 面 `/v1/chat/completions` 是**协议转译**（`billing_usage.source=claude_messages`、
  `usage_source=anthropic`、顶层 `output_tokens` 恒 0）；**Messages 面顶层字段干净**，无中转标记、协议未被改写。
- 能力面**全绿**：基础 15/15；工具闭环/并行工具/结构化随机串强绑定/视觉（带图 401 vs 文本 51 token）/
  长上下文 27406 input tokens/前缀缓存命中 5135 均成立。`effort` 档位差异仅 +5%（low 662 vs max 696），
  叠加 usage 伪造 → **effort 是否真实生效不可取证**。`thinking.display=summarized` 时 thinking 文本恒为空
  （摘要被剥离），流式 `thinking_delta` 内容也为空。未观测到 `refusal` 语义。
- **两条判据缺陷（已修，教训值得记住）**：
  1. `stop_sequences` **不能**用「让模型遇到某标记就停」来验证——模型可能提前自然收尾，会把「停止序列未生效」
     误判成失败。正确写法：要求模型输出一段**必然包含分隔符**的序列（如 `A1 B2 C3 D4 E5`），
     用该分隔符作 stop_sequence，断言输出在分隔符前被精确截断。修正后实测 `stop_reason=stop_sequence` ✓。
  2. `system` **不能**用「必须且只能输出某个固定串」来验证——Claude 会拒绝这类覆盖式指令
     （原文 `I can't follow an instruction to output only a fixed string regardless of context`），
     且该指令放在 **user** 消息里同样被拒 → 这是**模型对齐行为**，不是 system 未生效。
     正确写法：用**格式前缀约束**（如「每条回复必须以 [Q] 开头」），实测生效 ✓。
- 代码改动：`harness.py` 新增 `quota_exhausted_reason()` 并把 **403+quota 归类为 `blocked`**
  （原先会被记成 failed/warning，污染结论）；`cases.py` 重写 E17/E18 判据。
- 建议给平台 `fable5/` 套件也补两条：**「用量可信性」用例**（同提示改 `max_tokens` 两次调用，
  `output_tokens` 随上限变化即判信任级失败）与**「截断一致性」检查**
  （`output_tokens == max_tokens && stop_reason == "end_turn"` 为矛盾组合）。



## Fable 5 套件「执行测试报错」排查与修复（19:20~19:35）

**现象**：Web 提交 `{test_kind: fable, protocol: anthropic, base_url: https://i-token.ai,
model: claude-opus-5, cases: [FABLE5_FINGERPRINT]}` → 报错。

**1) 真因（阻断性）：`web/server.py` 的 `available` 用例集派发链漏了 fable 分支**
- `/api/run` 里 `available = ... KVV_CASES if kvv else DEEPSEEK_CASES if deepseek else GLM_CASES if glm
  else GPT56_CASES if gpt else GPT_IMAGE_CASES if gpt-image ...`，**没有 `FABLE5_CASES if fable`**
  → `available = {}` → `any(name not in available)` → 400「未知测试类型」，套件根本发不出去。
- 已插入 `FABLE5_CASES if test_kind == "fable"` 分支。此前只登记了 `protocols_for()` / script / env /
  `capability_case_payload` / `/api/cases` / 前端，**漏了这一处**。
- 教训已写入 MEMORY.md 的「Web 新增套件要登记的地方」清单。

**2) AUTH-F05 判定器缺陷（假 failed）**
- 原 `low_signal = low_thinking_chars or low_output_tokens` 是**跨指标**取值：实测 low 的
  `thinking_chars=720`、max 的 `thinking_chars=681`，被写成"两档完全相同（720）"→ 既漏判又误报。
- 改为逐指标对照（`compared_metrics`）：全部可比指标完全相同 → failed；**非单调**（有的更大有的更小）
  或方向与预期相反 → warning；均无产物 → blocked；**两侧皆 0/缺失的指标不纳入对照**（否则
  "usage 缺 output_tokens + 摘要未透传"会被误判成剥参）。

**3) AUTH-F07 判定口径错误（假 failed）**
- 原判"响应 model 须属 Fable 家族"。用 `claude-opus-5` 跑 Fable 5 指纹时响应与请求完全一致，
  却记 failed 并称"疑似静默降级/中转替换"——把"用户选错模型"误报成"网关替换"（自造契约）。
- 改为比较响应 vs **请求** model：`_same_model_name()` 容忍版本后缀；一致且属 Fable 家族 → passed；
  同族别名归一化（`fable-5`→`claude-fable-5`）→ passed；响应是别族 → failed；
  **请求本身非 Fable 但响应一致 → warning**（提示"Fable 身份结论不适用，请改用 claude-fable-5"）。

**4) 新增：账号/额度/分组权限被拒 → 统一 blocked 且写自解释理由**

  → `_note_account_limitation()` 回退解析原文（新增 `_as_json_dict()`），否则流式用例的额度/权限
  拒绝退化成"无原因的 403"。
