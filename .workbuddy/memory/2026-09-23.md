# 2026-09-23

## mux.la（中转站）kimi-k3 连通性排查

**现象**：web 测试页「测试连通性」报 `HTTP 429 {"error":{"message":"All upstream attempts failed",...}}`
（Claude Messages 协议，BASE URL `https://mux.la`，模型 `kimi-k3`）。

**结论 1：429 是 mux.la 站方上游渠道故障，与本地配置/key/代理无关**
- `GET https://mux.la/v1/models` 用同一 key 返回 200 → key 有效，且该 key 只挂 `kimi-k3` 一个模型。
- 换模型名得到旁证：`claude-3-5-sonnet-20241022` / `kimi-k2` → `model_not_found`「分组 **Kimi-K3** 下模型 X 无可用渠道（distributor）」。
  说明该 key 属 `Kimi-K3` 分组，`kimi-k3` 是唯一渠道，而这一条渠道当前全挂。
- 已验证排除：Claude 协议 x-api-key、OpenAI 协议 Bearer、直连/沙箱代理/Clash 代理、HK/SG/TW/KR/DE 多节点 —— 全部得到同一个 429。
- 待站方修复；报障时附 request id（如 `202609230313354473400788268d9d6XVeJRSuX`）。

**结论 2：代理层确有问题，但不是 429 的成因**
- 平台 `ApiConfig.trust_env` 默认 **False**（`volcperf/config.py`），即「测试连通性」**忽略 HTTP_PROXY/HTTPS_PROXY 走直连**；
  而 mux.la 直连在本机当前**不通**（httpx `SSL: UNEXPECTED_EOF_WHILE_READING`，mihomo `DIRECT` delay 也 Timeout），
  必须依赖 Clash Verge 的 **TUN 模式**接管直连流量才能到达。
- 经 Clash 7897 的链路**不稳定**：5 次实测中 3 次拿到 429，另 2 次出现 SSL EOF / 30s 超时。所以偶发报连接类错误属链路抖动。
- 出口节点：规则未给 mux.la 定制，落到 `MATCH,✈️Final → Proxies → 🇭🇰 Hong Kong 01`，出口 IP `154.92.130.94`。

**可操作项**
- 稳定链路：Clash 增加 `DOMAIN-SUFFIX,mux.la,✈️Final`，或设置 `VOLC_TRUST_ENV=true` + `HTTPS_PROXY=http://127.0.0.1:7897`；也可换 HK 05/06/11、SG 节点。
- 本机环境备忘：Clash Verge（mihomo v1.19.31，TUN + fake-ip 198.18.0.0/16，mixed-port 7897，控制 socket
  `/var/run/clash-verge-service/users/501/verge-mihomo.sock`）；项目 venv 在 `.venv/`。

## 修复：Web 探针未共用 VOLC_TRUST_ENV（已改代码）

**根因**：`.env` 里的代理配置一直是齐全的（四个大小写变量 + `VOLC_TRUST_ENV=true`，`start.sh` 用 `set -a` 导出），
但 `web/server.py` 构造探针配置时写的是 `ApiConfig(...)` **没传 `trust_env`**，回落到 dataclass 默认 `False`
→「测试连通性」永远走直连，`.env` 完全不起作用。而同一页面的「查询模型」用的是 `httpx.get(...)`（默认
`trust_env=True`），于是出现"模型查得到、连通性检查却连不上"的割裂现象。

**改动**（4 个文件）：
- `volcperf/config.py`：新增 `trust_env_enabled()` 统一判定（`_TRUTHY` 常量），`ApiConfig.from_env()` 复用它。
- `web/server.py`：`/api/connectivity/check` 传 `trust_env=trust_env_enabled()`；
  `/api/models/query` 显式传同名参数，与探针口径一致。
- `tests/test_connectivity.py`：新增 `TrustEnvFlagTests`（缺省/真值/假值/from_env 传播）。
- `tests/test_web.py`：新增 `test_connectivity_check_shares_trust_env_switch_with_load_tests`，
  并断言模型查询显式传入 `trust_env`。

**验证**：`tests` 全量 119 passed；唯一失败 `tests/test_kvv.py::test_existing_official_runtime`
是 `vendor_verifier/.venv` 缺失导致的环境问题，与本次无关。
端到端：重启后调 `/api/connectivity/check`（anthropic + `https://mux.la` + `kimi-k3`）返回
`http_status: 429`（网关真实响应）而非之前的 `ConnectError: SSL UNEXPECTED_EOF_WHILE_READING`，
说明探针已按预期走 7897 代理。

**注意**：`VOLC_TRUST_ENV=true` 会让**正式压测**也经代理，延迟/带宽会受代理节点影响；
性能测试与连通性诊断口径不同，解读报告时留意。
