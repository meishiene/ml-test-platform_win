### 连接踩坑（重要，本机环境通用）

首次连接报 `server closed the connection unexpectedly`，但 `nc -z` 显示端口"开放"。
根因不是数据库：`route -n get 192.168.1.82` → `gateway 198.18.0.1, interface utun1024`。
**Clash TUN 的 fake-ip 网段是 198.18.0.0/15**，本机在 `192.168.5.9/24`，跨网段流量被 TUN 全量接管；
TUN 对任意端口都立即接受 TCP 再断开，所以端口探测结果全是假象。
当时核心是 `mode: global` —— **global 模式忽略 rules**，即使订阅里有 `IPCIDR 192.168.0.0/16 -> 🎯Direct` 也不生效。

解法（已复原）：临时 `PATCH /configs {"mode":"rule"}` → 内网命中 Direct → 连库；跑完切回 `global`。

```bash
SOCK=/tmp/verge/verge-mihomo.sock
curl -s -X PATCH --unix-socket $SOCK http://localhost/configs \
  -H "Content-Type: application/json" -d '{"mode":"rule"}'    # 用完改回 "global"
```

psql 客户端本机没装，用 `docker run --rm -i -e PGPASSWORD=... postgres:16-alpine psql "host=... ..." -f - < q.sql`。

### 对账口径（易错点，下次直接照抄）

- 账务日 `Asia/Shanghai`，左闭右开；`quota` 为主单位，USD = quota × 0.000002；切换日 `2026-09-01`。
- 采购侧：`billing_daily_fact."purchaseRawQuota"` ↔ `platform_consume_log.quota`，且必须排除 `"tokenName" <> '模型测试'`。
- 销售侧：`salesQuota` ↔ `newapi_log.quota where type=2`。
- **不能在 `modelName` 维度对账**：`billing-candidate.sql.ts` 里 matched 分支的 modelName 取**下游**名
  （`COALESCE(NULLIF(BTRIM(d."modelName"),''),'')`），unmatched 分支取**上游**名。两套命名体系必然错配。
- **账单 `channelId` 是本地 `channel.id`，日志 `newapi_log.channel` 是上游 `newapiChannelId`**，两个 id 空间，
  必须先 `JOIN channel ON channel."newapiChannelId" = newapi_log.channel` 再比。
  （实测映射：101→17 lxm 中转-A、102→19 测试平台-6、104→18 测试平台-10、105→21 admin-平台）

### 批次源行数的口径（曾误判为不一致）

`billing_generation_batch."sourceDownstreamRows"` 记的是**窗口内 `newapi_log` 全类型行数**（含 type=5/1001），
不是只算 type=2。逐日验证（批次 − 全类型）：09-12 0、09-13 0、09-14 0、09-15 0、09-16 0、09-17 0。
典型：09-13 批次 62900 = type2 57196 + type5 1667 + type1001 4037。
上游侧的 `sourceUpstreamRows` 则与 `platform_consume_log`（排除模型测试）**完全相等**，六天差 0。
