# 大模型通用测试与专项验收指南

> 适用对象：中转站、API 网关、云厂商托管模型、自建推理服务及其兼容层。  
> 本文是测试设计与验收文档，不修改任何运行代码。具体模型版本、接口字段和官方阈值以被测方当前公开文档为准。

## 1. 文档目的与测试原则

本指南用于回答三个问题：

1. 截图中已有的 DeepSeek V4 专项之外，还必须验证什么；
2. 如何为任意大模型建立可重复、可审计、可比较的测试集；
3. 国内外主流模型应增加哪些与其产品能力相关的专项测试。

测试结论必须区分以下状态：

| 状态 | 含义 | 是否计入通过 |
|---|---|---:|
| `passed` | 所有断言和证据要求满足 | 是 |
| `failed` | 模型或接口行为违反预期 | 否 |
| `error` | 执行异常、服务错误或证据损坏 | 否 |
| `blocked` | 前置能力不支持，后续测试无法解释 | 不直接判模型失败，但阻断相关能力准入 |
| `not_evaluable` | 缺少请求、数据、权限或有效断言 | 否，不能当作通过 |
| `warning` | 非阻断性偏差，需人工复核 | 按项目策略处理 |

“HTTP 200”“请求完成”“返回了文本”均不等价于模型能力通过。每条用例应保存请求、响应、流式原文、usage、时间戳、上游 request-id、模型标识、参数和判定依据。

## 2. 截图中已有的 DeepSeek V4 覆盖

截图中的测试项可归纳为以下五组：

| 已有测试 | 已覆盖内容 | 价值 |
|---|---|---|
| `DS_V4_P0` | 思考开关与强度、reasoning 回传、流式思考、工具调用及历史回放、JSON 输出、Context Cache、user_id 隔离、Session 连续性 | 验证最核心的模型能力和中转站是否保留关键字段 |
| `DS_V4_P1` | Strict Tool、非法 Schema、Prefix Completion、FIM、Anthropic 映射、Responses API | 验证扩展 API 和高级开发能力 |
| `DS_V4_P2` | usage、SSE 结束、Stop、参数边界、非法消息、Tool Choice、Responses/Anthropic 基础契约 | 验证协议正确性、错误语义和边界行为 |
| `DS_V4_FINGERPRINT` | 动态工具、随机 JSON Schema、多轮记忆、reasoning 字段、SSE 完整性、静默吞参对照 | 识别降级、错路由、字段吞掉或伪兼容 |
| `DS_CONTRACT` | 身份、输出、usage、SSE、错误等公共探针 | 给专项测试提供统一基础契约 |

这些测试仍不足以形成完整的大模型验收。尤其缺少多轮压力下的稳定性、知识与推理质量、长上下文真实性、RAG/Agent 工作流、安全红队、隐私、成本、可观测性和版本回归。

## 3. DeepSeek V4 之外必须补充的测试

### 3.1 能力质量测试

| 测试项 | 测试内容 | 作用 | 必要性 | 测试方法与建议指标 |
|---|---|---|---|---|
| 基础指令遵循 | 单指令、多约束、否定约束、格式约束、优先级冲突 | 判断模型是否按要求完成任务 | 所有应用的基础能力 | 准备 100–500 条人工标注集；计算任务成功率、约束满足率、格式合法率 |
| 指令层级与冲突 | system/developer/user/tool 指令冲突、引用文本内伪指令、后置覆盖 | 验证模型遵守可信指令层级 | 防止用户或外部文档覆盖系统规则 | 用成对用例只改变冲突来源；统计高优先级指令保持率和注入成功率 |
| 中文与多语言 | 简体/繁体、英文、日文、韩文及中英混合；翻译、术语保持、语言切换 | 判断目标用户语言质量 | 国内业务常跨语言，且中转站可能改变编码或 system 指令 | 按语言和任务分层抽样；人工评分 + 语义相似度；报告各语言最低分，不只看平均值 |
| 数学与符号推理 | 算术、代数、几何、概率、单位换算、表格计算 | 测试可验证推理能力 | 生成式答案容易“看似合理但算错” | 使用带最终答案和过程标签的数据；精确匹配最终答案，单独统计过程合理性和拒答率 |
| 逻辑与复杂推理 | 演绎、归纳、约束满足、多跳推理、反事实、规划 | 检验模型能否稳定组合信息得出结论 | Agent、分析和决策支持依赖此能力 | 使用可程序验证的合成题和人工题；改变表述并交叉验证答案，统计一致率和最终答案正确率 |
| 事实性与幻觉 | 已知事实、未知事实、时间敏感事实、冲突资料、诱导性问题 | 衡量是否编造内容 | 生产系统的主要风险之一 | 提供可核验来源；测事实正确率、引用支持率、无依据断言率、适当拒答率 |
| 置信校准 | 要求概率、置信等级或可回答/不可回答判断 | 检验模型的自信程度是否匹配正确率 | 高置信错误比普通错误更难治理 | 混合易题、难题和不可答题；计算 Brier Score/ECE，并统计高置信错误率 |
| 代码生成与修复 | 多语言、单元测试修复、依赖升级、异常处理、安全编码 | 判断工程生产力 | 代码错误可能造成直接损失 | 用固定仓库和隐藏测试；统计 pass@1/pass@k、编译率、测试通过率、漏洞率、修改范围 |
| 结构化输出 | JSON Schema、枚举、嵌套数组、空值、Unicode、超长字段 | 验证下游可解析性 | 业务编排通常依赖严格结构 | 每条输出用 JSON Schema 校验；统计语法通过率、语义字段通过率、重试后通过率 |
| 长文本理解 | 长文摘要、跨段检索、表格/列表定位、长文问答 | 验证上下文窗口不是只“能接收” | 声明窗口与真实可用窗口可能不同 | 在 4K/16K/32K/64K/128K 等长度插入唯一标记；测试首、中、尾位置召回率及干扰项误召回率 |
| 视觉/音频/视频（如支持） | OCR、图表、空间关系、时间顺序、跨模态问答 | 验证多模态端到端质量 | 多模态接口常被中转站错误降级为文本 | 固定媒体哈希和版本；测识别准确率、定位准确率、跨模态推理正确率、媒体失败率 |
| 公平性与偏见 | 性别、年龄、地域、民族、职业等敏感属性的成对样本 | 发现不应由敏感属性导致的答案差异 | 招聘、金融、客服等场景存在合规风险 | 使用除敏感属性外完全相同的配对用例；统计决策差异率、贬损率和拒答差异 |
| 基准污染与记忆 | 公开题原文、改写题、新生成题、时间切分题 | 判断高分是否来自记忆而非能力 | 主流公开 benchmark 易进入训练数据 | 比较原题与语义等价改写、新题表现；检查异常逐字复现，最终准入以隐藏集为主 |

### 3.2 可靠性与性能测试

| 测试项 | 测试内容 | 作用 | 必要性 | 测试方法与建议指标 |
|---|---|---|---|---|
| 冒烟与长稳 | 低负载连续请求、不同参数、不同协议 | 快速发现路由和基础故障 | 每次发布都应执行 | 10–20 次冒烟；再做 1–24 小时长稳；记录成功率、错误类型、结论漂移 |
| 并发容量 | 并发 1、2、4、8…逐档升压 | 找到服务可用容量 | 中转站的限流和排队会改变模型体验 | 固定输入/输出分布；每档至少 100 个有效样本；报告 RPM、TPM、并发、饱和点、排队斜率 |
| 延迟分位 | 首 token、首可见 token、每 token、完整响应 | 评估交互体验和容量退化 | 平均值会掩盖尾延迟 | 分开记录 TTFT、TTFC、TPOT、E2E；报告 P50/P90/P95/P99，不跨口径比较 |
| 输出稳定性 | 相同 prompt 多次采样、不同温度和 seed | 识别随机性和路由漂移 | 评测集结果可能因随机波动失真 | 固定 seed（若支持）；同题 5–20 次；报告通过率均值、标准差、最差批次 |
| 超时与重试 | 连接超时、读取超时、429、5xx、断流、重试 | 验证故障恢复不重复扣费或污染上下文 | 真实生产中不可避免 | 使用可控 mock 和真实低成本端点；检查退避、幂等键、重试次数、重复请求率 |
| 流式健壮性 | 分片边界、空 delta、Unicode 拆分、提前断流、重复 DONE | 验证客户端能安全消费 SSE | 流式解析错误会造成截断答案或工具误执行 | 保存原始事件；检查事件顺序、结束事件、usage、UTF-8 完整性和重连行为 |
| 输入与协议鲁棒性 | 空输入、超长字段、畸形 JSON、重复键、异常 Unicode、错误 MIME、未知字段 | 确保错误输入被明确拒绝且服务不崩溃 | 网关边界输入不可避免，也可能成为攻击入口 | 用边界值和模糊测试逐项注入；检查 4xx/错误码一致性、无 5xx、无敏感堆栈泄漏 |
| 限流与公平性 | 单 key、多个 key、租户隔离、突发流量 | 验证中转站容量治理 | 防止单租户拖垮整体服务 | 逐级升压，观察 429 的 Retry-After、配额消耗和其他租户成功率 |
| 成本与计费 | 输入/输出 token、缓存 token、图像/音频计费、重试计费 | 保护预算并核对供应商账单 | usage 错误会直接造成成本失控 | 用已知 token fixture 对照 tokenizer；核对 prompt/completion/total、缓存折扣和重试是否重复计费 |
| 故障切换与恢复 | 上游不可用、路由切换、进程重启、队列恢复、区域故障 | 验证故障期间服务行为和数据一致性 | 生产可用性不能只靠正常路径测试 | 在非生产环境注入故障；验证熔断、降级标识、会话一致性、恢复时间和无重复副作用 |

### 3.3 上下文、记忆与工具测试

| 测试项 | 测试内容 | 作用 | 必要性 | 测试方法 |
|---|---|---|---|---|
| 多轮记忆 | 同一会话引用前文、跨轮修改、长对话压缩 | 验证服务端或客户端会话语义 | Session 丢失是中转常见问题 | 每轮加入唯一事实；穿插干扰轮；检查正确引用、压缩摘要和 token 增长 |
| 租户/用户隔离 | 不同 user_id、API key、会话、缓存前缀 | 防止数据串线 | 这是安全底线 | 两个身份交错请求相同/相似前缀；要求不可读取对方事实、缓存和工具结果 |
| 工具调用闭环 | 工具选择、参数生成、执行结果回传、并行工具、错误工具结果、二次调用 | 验证 Agent 基础闭环 | 只测“能生成 tool_call”不够 | 使用可审计的假工具；校验名称、JSON 参数、顺序、call_id、历史回放和最终答案 |
| 工具安全 | 工具白名单、权限、参数边界、提示注入、越权调用 | 控制 Agent 的实际副作用 | 工具调用比纯文本风险更高 | 构造越权和注入用例；所有未授权调用必须被阻止并留证 |
| RAG | 检索命中、引用、冲突文档、无答案、权限过滤、时间版本 | 验证知识增强是否真正有效 | “有引用”不等于“引用支持答案” | 固定文档快照和检索结果；测召回率、答案支持率、引用精确率、拒答正确率、权限泄漏率 |
| Agent 任务 | 规划、状态机、循环上限、失败恢复、人工接管、最终交付 | 验证端到端任务完成能力 | 单轮 benchmark 不能代表 Agent | 用沙箱和确定性工具；记录每一步轨迹；测任务成功率、步骤数、无效调用率、超时率、成本 |

### 3.4 安全、合规与治理测试

| 测试项 | 测试内容 | 作用 | 必要性 | 测试方法与建议指标 |
|---|---|---|---|---|
| 越狱与提示注入 | 角色扮演、编码/翻译绕过、间接注入、长上下文注入、多语言绕过 | 验证安全策略不易被改写 | 公网模型必须具备 | 建立攻击语料库，分级执行；统计高风险漏判率、拒答正确率、误报率和结论翻转率 |
| 有害内容 | 暴力、违法、仇恨、未成年人、色情、自伤、危险化学/生物、网络攻击 | 验证风险边界 | 需要满足业务和地区合规 | 每类设置允许、拒绝、转介和模糊边界样本；双人标注，报告宏平均和最差类别 |
| 隐私与数据外泄 | prompt 中的 PII、系统提示、训练数据诱导、跨会话泄漏 | 保护用户和平台机密 | 中转站会接触原始请求和响应 | 使用金丝雀字符串和假 PII；多租户交叉回放；检查日志脱敏、响应泄漏和缓存隔离 |
| 供应链与模型真实性 | 模型名、版本、路由、能力指纹、静默降级 | 证明请求确实到达目标模型 | 中转站可能以兼容接口伪装模型 | 动态 Schema、必需工具、reasoning、上下文长度、错误语义多探针交叉验证；不能仅凭 `model` 字段认定 |
| 审计与可追溯 | request-id、时间、模型版本、配置、原始证据、操作者 | 支持事故定位和复测 | 没有证据的分数不可复核 | 每条记录生成不可变 ID；敏感字段脱敏；报告可由原始记录重算 |
| 数据驻留与删除 | 地区路由、日志留存、删除请求、供应商转发 | 满足合同与监管要求 | 企业客户常有地域限制 | 用合成数据验证路由和删除；检查日志、缓存、备份及供应商侧确认记录 |

## 4. 通用测试集设计规范

### 4.1 用例字段

每条原子用例建议包含：

```yaml
id: QA-JSON-001
category: structured_output
priority: P0
protocol: openai
model: target-model
input:
  messages: [...]
parameters:
  temperature: 0
expected:
  status: 200
  json_schema: {...}
  semantic_assertions: [...]
evidence:
  required: [request, response, usage, request_id, timestamps]
cost_class: low
destructive: false
```

用例应满足单一目的、可重复、可判定、可追溯。场景描述但没有实际请求、数据或断言的案例只能标为 `not_evaluable`，不得自动生成一个“看起来能跑”的请求。

### 4.2 数据集分层

- **Smoke**：每个协议、模型和关键能力 1–3 条，发布前分钟级完成。
- **P0 Admission**：身份、基础对话、结构化输出、工具、流式、usage、安全底线、租户隔离。
- **P1 Regression**：长上下文、RAG、代码、数学、多语言、缓存、重试、成本。
- **P2 Exploration**：新能力、边界行为、供应商差异和研究性指标。
- **Red Team**：独立维护攻击集，不能与开发调参集完全重合。

数据集必须有版本、来源、许可证、标注指南、答案版本、难度标签、语言标签和泄漏风险说明。训练集、调参集、验收集和隐藏集分离；同一题不得同时用于提示优化和最终评分。

### 4.3 评分与统计

1. 对精确任务使用 exact match、Schema 校验或隐藏单元测试；对开放任务使用双人或专家评分。
2. 质量指标至少报告样本数、通过数、失败数、不可评估数、95% 置信区间和按子集分组结果。
3. 性能指标使用 P50/P90/P95/P99；长稳额外报告错误突发、内存/队列趋势和按小时分桶结果。
4. 安全指标同时报告漏判和误报，不能只报告拒答率；拒答过多同样可能损害业务。
5. 对随机模型固定 temperature/top_p/seed（若供应商支持），并报告实际生效参数，识别被静默忽略的参数。
6. 通过阈值应预先登记。测试完成后不得根据结果倒推阈值；任何阈值变更都要递增测试集版本并保留旧结果。

### 4.4 推荐准入门槛

门槛需按业务调整，以下是通用起点：

| 层级 | 建议门槛 |
|---|---|
| P0 协议 | 身份和路由正确率 100%；SSE 完整性 100%；usage 完整率 100%；无未授权工具调用 |
| P0 稳定性 | 冒烟成功率 100%；正式批次成功率 ≥99%；所有失败可分类且有原始证据 |
| P0 安全 | 高风险漏判率为 0 或符合业务批准阈值；跨租户泄漏为 0 |
| 结构化输出 | Schema 合法率按业务要求，关键交易接口建议 ≥99.9%；不得依赖无界重试掩盖模型失败 |
| 性能 | 按服务等级协议设定 TTFT/TTFC/TPOT 和吞吐阈值；必须同时满足分位延迟与成功率 |
| 质量 | 以基线模型为对照，关键集不低于基线；任何严重子集回退都需要人工签字 |
| 证据 | 每个通过案例都有请求、响应、判定和环境元数据；缺证据不得准入 |

## 5. 国内主流大模型专项测试

下表是针对常见国内模型/产品家族的测试重点。模型名称和接口能力会随版本变化，执行前应从官方文档核对当前模型 ID、区域、上下文和计费规则。

| 模型/家族 | 测试内容 | 作用与必要性 | 关键验证方法 |
|---|---|---|---|
| DeepSeek V4 Pro/Flash | 思考模式、reasoning 字段、思考强度、Strict Tool、Prefix/FIM、Context Cache、Responses/Anthropic 映射、满血指纹 | 验证 DeepSeek 特有接口是否被中转完整保留，并识别错路由或降级；对本次被测对象属于 P0 | 使用本仓库已有 `DS_V4_P0/P1/P2/FINGERPRINT`；再补长上下文、RAG、代码修复、红队和长稳 |

## 7. 中转站专项验收清单

中转站除了测试目标模型，还必须测试“转发层是否保持语义”：

- 请求：system/developer/user/tool 消息顺序、Unicode、图片/音频 MIME、未知字段和自定义 header 是否完整保留；
- 参数：temperature、top_p、max_tokens、seed、reasoning effort、tool_choice、response_format 是否透传或明确拒绝；
- 响应：模型 ID、finish reason、reasoning、tool_calls、引用、usage、错误码和错误消息是否保持；
- 流式：事件顺序、空事件、分片拼接、断流、重连、DONE、usage trailer 和代理缓冲；
- 路由：模型别名、版本 pin、区域、fallback、灰度比例和故障切换是否可观测；
- 计费：输入/输出/缓存 token、重试、失败请求和多模态计费是否与供应商账单一致；
- 安全：API key 不落日志，prompt/response 脱敏，租户隔离，审计字段完整，取消请求确实停止上游；
- 兼容：OpenAI、Responses、Anthropic、Gemini 或厂商原生协议分别建立契约，不用一个“兼容成功”结论覆盖全部协议。

## 8. 推荐执行流程

1. **冻结版本**：记录模型 ID、网关 commit、API 版本、区域、配置、数据集版本和阈值版本。
2. **连通性探测**：先验证 DNS/TLS、鉴权、模型身份、最小请求和代理设置；失败时停止正式测试。
3. **冒烟**：跑各协议和关键能力的低成本 P0，用于排除配置问题。
4. **契约与真实性**：跑身份、错误、SSE、usage、工具、Schema 和动态指纹。
5. **质量与安全**：跑固定离线集、RAG/Agent 工作流和红队集，记录人工复核项。
6. **性能与成本**：先单并发基线，再逐档并发、长稳、故障注入和成本对账。
7. **回归比较**：与上一版本、基线模型和目标 SLA 比较；分析按子集的回退。
8. **准入评审**：按 P0/P1/P2 输出通过、阻断、失败、不可评估和遗留风险；不可评估项必须指定补测责任人和日期。

推荐的报告目录：`metadata.json`、`summary.json`、`validation.json`、`requests.jsonl`、`errors.csv`、`metrics.csv`、`report.md`、数据集版本和人工复核记录。原始证据应支持从汇总指标回放到单条请求。

## 9. 最小可执行测试包

资源有限时，至少执行以下 24 组：

1. 连接、鉴权、模型身份；
2. 单轮/多轮基础问答；
3. system/developer 优先级；
4. 中文、英文、中英混合；
5. JSON Schema；
6. 工具单调用；
7. 工具错误与重试；
8. 流式 SSE；
9. usage 与 token 对账；
10. 取消、超时、429、5xx；
11. 4 档上下文长度；
12. 多租户/缓存隔离；
13. 事实性与未知问题拒答；
14. 数学与代码隐藏测试；
15. 基础 RAG 引用；
16. 一个 Agent 闭环；
17. 有害内容拒答；
18. 提示注入和越狱；
19. PII 与金丝雀泄漏；
20. 并发 1/4/16/峰值；
21. 1 小时长稳；
22. 重试不重复计费；
23. 版本/别名/区域路由；
24. 与上一版本的质量、延迟、成本回归。

这 24 组只能作为最低准入包，不能替代针对具体模型的多模态、搜索、缓存、推理强度、官方 KVV 或厂商原生能力测试。
